# 交互重算与模型身份修复记录

验证日期：2026-10-08。基线提交：`4f5051f`。运行环境为项目虚拟环境 Python 3.12.14、Streamlit 1.64.0、Pandas 2.3.3；本次未修改依赖。

## 原因与修复

1. 原页面在完整重跑时重复校验原始数据，并通过多个指标调用反复解析标准数据。预览和概览改为当前会话缓存，按文件内容指纹、已应用映射、币种、日期及商品条件失效。重新映射仍从原始数据生成，换文件会清空缓存。
2. 高级工具输入框原本在表单外，按钮依赖输入非空才启用。失焦会触发完整重跑，必须等待重算后按钮才可用。现采用表单统一提交，按钮始终可点，空输入本地提示；fragment 限制高级工具重跑范围。
3. 单次概览、周期比较和诊断中的多个指标函数共享只读解析快照，计算结束即释放作用域。后续调用重新解析其输入，不采用可能忽略 DataFrame 变化的全局缓存。商品目录直接按精确商品标识生成，不再通过全周期商品对比获得名称。
4. 未发现固定 Claude 答复或将 DeepSeek 配置路由到 Claude 的代码。原高级查询把模型身份交给模型自由回答，未告知实际调用配置，旧结果也可能在切换模型后继续显示。现由应用配置回答纯身份问题、向业务提示词注入配置、显示结果配置来源，并清理模型切换后的旧高级结果。DeepSeek 构造器仍使用 `https://api.deepseek.com`。

## 真实月度数据复测

输入为 UCI Online Retail 的 2011 年 11 月原始明细 CSV，84,711 行，GBP，未去重、未清洗。通过常规文件读取和字段映射准备独立测试会话；未向用户浏览器会话注入数据，未增加专用 URL、自动下载或自动导入入口。

使用 Streamlit AppTest，分别在修改前后测量一次相同步骤。单位为秒，非浏览器端计时，非并发或模型性能测试。两次初始化前均已完成文件读取及字段映射，初始化包含第一次概览计算。

| 步骤 | 修改前耗时 | 修改后耗时 | 修改前质量／指标解析次数 | 修改后质量／指标解析次数 |
| --- | ---: | ---: | ---: | ---: |
| 初始化页面 | 18.161 | 4.366 | 1 / 8 | 0 / 2 |
| 启用高级工具 | 19.589 | 0.051 | 1 / 8 | 0 / 0 |
| 输入需求后强制重跑（未执行） | 15.102 | 0.042 | 1 / 8 | 0 / 0 |

修改后提交“你是什么模型”耗时 0.040 秒，无重新解析，无模型调用，结果为配置中的 DeepSeek / deepseek-chat。所有步骤 AppTest 异常数为 0。AppTest 的 `set_value(...).run()` 主动强制重跑；真实前端表单输入本身不提交，不能将该测试理解为每次键盘输入均耗时 0.042 秒。第一次导入、改变映射或周期、真实模型执行仍需要相应计算或网络等待。

## 回归验证与边界

新增 7 项回归测试，完整测试共 57 项通过，覆盖：

- 同映射校验复用、改价映射重新计算，文件／币种／日期／映射依赖失效及缓存有界。
- 周期对比与诊断只解析一次，跨数据集嵌套、异常清理、之后修改输入不会读取旧快照。
- 高级工具表单、空输入提交、输入时无模型调用、不重算数据、切换 Claude 和 DeepSeek 后旧结果清理。
- 两个问答入口均按应用配置回答纯身份问题，不把带身份词的业务问题拦截为身份问答。
- 真实 LangChain Pandas Agent 调用 `python_repl_ast` 完成数量求和，工具返回结果进入模型消息，提示词包含 DeepSeek 配置。仅模型传输使用确定性模拟，编排与 Pandas 工具实际执行。

未读取用户浏览器会话中的 API Key，本次未调用真实 DeepSeek API；未独立验证服务端实际模型身份。AppTest 不代表实际浏览器视觉验收，浏览器自动化初始化失败的限制仍存在。公开数据、密钥、虚拟环境及本地输出不提交 Git。

## 实际服务加载旧代码的补充修复

同日用户反馈启用高级工具仍慢，进一步检查正在运行的 8501 服务。磁盘代码虽为 `f298859`，独立 WebSocket 会话收到的实际界面仍没有当前模型配置说明；高级工具开关的 `delta.fragment_id` 为空，输入框没有表单，空输入时执行按钮仍禁用。这证明旧进程保留了上次修复前的导入模块，之前的健康检查未覆盖代码是否更新。该会话仅加载公开模拟样例，未读取或操作用户现有浏览器会话。

重启且仅重启已核对可执行路径、项目及端口的本地服务，加载新代码；新增 `.streamlit/config.toml`，为本地开发使用轮询文件监控和保存后重跑，排除 `.venv`、`outputs` 及原始／私有／处理后数据目录。没有修改模型、指标计算或用户上传流程。已有进程必须重启一次才能读取该配置。

随后在新的独立会话中，通过实际服务的常规文件上传接口上传同一份 84,711 行 CSV，选择 GBP 并应用映射，发送开关交互，连续一次验证结果如下：

| 交互 | 服务响应耗时（秒） | 实际返回 |
| --- | ---: | --- |
| 启用高级工具 | 0.137 | 6 个元素，全部属于高级工具 fragment |
| 关闭高级工具 | 0.089 | 2 个元素，全部属于高级工具 fragment |
| 再次启用 | 0.080 | 6 个元素，全部属于高级工具 fragment |

三次均返回 `FINISHED_FRAGMENT_RUN_SUCCESSFULLY`，没有重绘其他页面；输入框属于 `commerce_advanced_form`，空输入执行按钮可点击。未调用模型。这是实际后台服务交互响应计时，包含本机 WebSocket 通信，不是浏览器视觉渲染计时或并发性能承诺。

另外临时添加无业务影响的注释触发文件内容变化，实际服务在 0.550 秒后完成自动整页重跑，随后恢复原文件字节；验证了轮询与自动加载路径，未保留注释或修改用户数据。测试脚本、测量输出及 CSV 仍在 Git 忽略范围。浏览器自动化本轮仍初始化失败，不能宣称已完成浏览器视觉验收。
