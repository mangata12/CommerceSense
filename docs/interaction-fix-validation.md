# 交互重算与模型身份修复记录

验证日期：2026-10-08。基线提交：`4f5051f`。运行环境为项目虚拟环境 Python 3.12.14、Streamlit 1.64.0、Pandas 2.3.3；本次未修改依赖。

## 原因与修复

1. 原页面在完整重跑时重复校验原始数据，并通过多个指标调用反复解析标准数据。预览和概览改为当前会话缓存，按文件内容指纹、已应用映射、币种、日期及商品条件失效。重新映射仍从原始数据生成，换文件会清空缓存。
2. 高级工具输入框原本在表单外，按钮依赖输入非空才启用。失焦会触发完整重跑，必须等待重算后按钮才可用。现采用表单统一提交，按钮始终可点，空输入本地提示；fragment 限制高级工具重跑范围。
3. 单次概览、周期比较和诊断中的多个指标函数共享只读解析快照，计算结束即释放作用域。后续调用重新解析其输入，不采用可能忽略 DataFrame 变化的全局缓存。商品目录直接按精确商品标识生成，不再通过全周期商品对比获得名称。
4. 未发现固定 Claude 答复或将 DeepSeek 配置路由到 Claude 的代码。原高级查询把模型身份交给模型自由回答，未告知实际调用配置，旧结果也可能在切换模型后继续显示。现由应用配置回答纯身份问题、向业务提示词注入配置、显示结果配置来源，并清理模型切换后的旧高级结果。DeepSeek 构造器仍使用 `https://api.deepseek.com`。

使用 Streamlit AppTest，分别在修改前后测量一次相同步骤。单位为秒，非浏览器端计时，非并发或模型性能测试。两次初始化前均已完成文件读取及字段映射，初始化包含第一次概览计算。

重启且仅重启已核对可执行路径、项目及端口的本地服务，加载新代码；新增 `.streamlit/config.toml`，为本地开发使用轮询文件监控和保存后重跑，排除 `.venv`、`outputs` 及原始／私有／处理后数据目录。没有修改模型、指标计算或用户上传流程。已有进程必须重启一次才能读取该配置。

随后在新的独立会话中，通过实际服务的常规文件上传接口上传同一份 84,711 行 CSV，选择 GBP 并应用映射，发送开关交互，连续一次验证结果如下：

## 绘图请求进入查询 Agent 的修复

默认工具类型为“自然语言查询”，原版不根据需求切换工具。该路径使用 Pandas Agent、最多 4 轮，只返回文字；即使模型执行了绘图代码，也不会把 Figure 返回页面。“Agent stopped due to max iterations”来自该循环停止输出，而自由绘图函数没有这条循环。未取得用户原请求的逐轮记录，不能断言当时每轮失败的具体代码或数据原因。

新增轻量规则路由：默认查询模式中的明确绘图需求转到自由绘图，页面展示实际工具；普通查询、明确不画图及显式选择的数据处理模式不改变。绘图继续使用 LangChain 提示词链，一次模型代码响应后执行并展示 Figure；兼容 Python Markdown 代码围栏，统一执行命名空间供列表推导式使用，拒绝空图，清理本次图形管理器而不关闭其他图。测试另外复现 Windows Tk 图形后端在线程内报错，改为 Agg 后端输出 PNG。

高级查询统一采用已验证的 `tool-calling`，保留 4 轮限制；超限抛出中文错误，不再作为成功答案显示。使用实际工具回调记录输入、输出与状态，保留已完成结果和问题；Python REPL 返回的错误字符串标为失败，不展示内部推理。

新增 7 项回归，完整 64 项测试通过。覆盖自动路由、同名不同编号且含冲销的柱状图金额、PNG 输出、Markdown 围栏、推导式命名空间、源数据与其他图不受影响、空／损坏／受阻代码、真实 LangChain 循环超限、超时前工具证据以及 AppTest 页面显示图像和失败状态。

另用同一份 84,711 行 GBP 月度数据实际生成前 10 商品净销售额柱状图，10 根柱子的金额全部与确定性商品贡献函数的当前周期整数分结果一致，PNG 已生成并目视检查。模型传输为确定性模拟；实际执行 LangChain、Pandas、Matplotlib 及页面展示，不代表真实 DeepSeek 生成代码质量验收。真实运行服务的独立上传会话也已核对返回新增绘图路由说明及 fragment 刷新，避免再次只验证磁盘代码。没有读取会话密钥、调用真实 API 或向用户页面自动导入数据。
